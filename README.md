# Smart Campus Management - CSE Department

A responsive campus operations website for the Department of Computer Science and Engineering. The public landing page introduces the department; the option menu opens Rooms & Resources, Maintenance Desk, Clash-Free Timetable, and Syllabus Progress.

## Included capabilities

- Deep-colour glass interface with responsive motion, hover states, icons, and animated spatial visualisation.
- Department overview based on the official PTU CSE information: establishment in 1987, technology-focused teaching and research, research areas, and laboratory ecosystem.
- Searchable room directory grouped by Classroom, Laboratory, Staff Room, HOD Room, Faculty Room, Seminar Hall, Toilet, and Other.
- Room condition language: **Available** (green), **Attention** (yellow), **Unavailable** (red), and **Empty** (black), plus totals for rooms, benches, seats, occupied seats, and each status.
- Faculty-controlled maintenance reporting and verification, with maintenance-staff repair updates. Issues are sorted Critical, High, Medium, then Low.
- Timetable rules that prevent lecturer, room, or student-section clashes and display lecturer, subject code, room, and time.
- Structured syllabus coverage by subject, semester, credit value, week, topics, and completion percentage.
- Identity capture with name only (no title/prefix), email, role, and access code. The application hashes the code before it is stored.
- A clean Supabase PostgreSQL schema with **no uploaded default records**.

## Supabase configuration

1. Create a new project at [Supabase](https://supabase.com/).
2. In **SQL Editor**, open `supabase/schema.sql`, copy all of it, and run it once.
3. Do not insert records if a fresh start is required. Add department rooms, faculty profiles, and subjects later through the Supabase Table Editor.
4. In **Project Settings > API**, copy the Project URL and the **service_role** secret key.
5. Copy `.env.example` to `.env` and enter the values. The service-role key must stay on the server and must never be put in `static/app.js`, HTML, or a public repository.

The schema enables row-level security. This Flask service uses the server-only service role key, which bypasses those client-facing restrictions. For a larger production deployment, replace self-registration with Supabase Auth, institutional email verification, role approval, audit trails, and narrowly scoped RLS policies.

## Initial data entry order

Because the database starts empty, enter operational data in this order using the Supabase Table Editor:

1. Sign into the website once for each faculty or maintenance staff member. This creates a `profiles` record with a hashed access code.
2. Add rooms in `rooms`, including a category, capacity, benches, occupied seats, resources, and condition status.
3. Add subjects in `subjects`, assigning each subject's `faculty_id` from the faculty profile ID and recording its semester and credits.
4. Faculty can then create timetable entries, report issues, and update syllabus progress through the website.

## Run locally

The project has not been started, and no database has been created locally.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# Fill in .env with the Supabase values
python app.py
```

Then open `http://127.0.0.1:5000`.

## Deploy on Render

1. Upload this folder to a private GitHub repository or connect it directly in Render.
2. In Render, choose **New > Blueprint** and select the repository. Render reads `render.yaml`.
3. Add `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` in the Render service environment settings; `FLASK_SECRET_KEY` is generated by the blueprint.
4. Deploy. The start command is `gunicorn app:app`.

## Academic references used in the interface

- The timetable workspace uses the supplied first-year timetable’s 2026-2027 Semester I schedule windows as a visible reference, but does not upload its entries into the database.
- The syllabus workspace identifies the supplied First Year B.Tech curriculum’s CSE-relevant Semester I courses and credit-oriented structure, but does not upload progress or subjects by default.
- The department landing page is based on the official PTU CSE page and should be reviewed if institutional content changes.
